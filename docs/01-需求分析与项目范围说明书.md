# 01 · 需求分析与项目范围说明书

## 1. 项目背景与目标

银行、证券、保险三类金融制度材料体量大、更新频繁、条文交叉引用多。业务人员在办理业务或
合规审查时，需要在多份《管理办法》《业务规范》《实施细则》之间反复查找，存在**检索慢、
定位难、版本易错**三个痛点。

本项目构建一个**基于 RAG（检索增强生成）的金融制度类知识问答系统**，目标是：

1. 把 PDF / Word / 图片形态的制度材料，统一解析为可检索的结构化知识资产；
2. 支持**关键词检索**（精确找条文）、**自然语言问答**（问业务问题）、**条文关联查询**（找配套规定）；
3. 每条答案给出**可点击核对的原文出处**（文档、条文号、页码），解决大模型幻觉问题；
4. 沉淀 **1000 条以上核心知识点**，形成可人工维护、可校验的金融制度知识库。

## 5. 核心用例

### UC-01 自然语言问答（主流程）

| 项 | 内容 |
| --- | --- |
| 参与者 | viewer / editor / admin |
| 前置 | 已登录，知识库已有一批已解析文档 |
| 主成功流 | 1. 用户输入问题「商业银行流动性覆盖率的最低要求是多少？」<br>2. 前端 `POST /qa/ask/stream`（SSE）<br>3. 后端改写查询、并行执行关键词 + 向量检索<br>4. RRF 融合 → 截断 Top-5 证据<br>5. 按 Prompt 模板组装上下文，调用 LLM 流式生成<br>6. 前端逐字渲染，答案中带 `[1][2]` 角标<br>7. 生成结束后返回引用列表与可信度<br>8. 落库 `qa_message` + `qa_citation` |
| 后置 | 该会话可在「问答历史」回看，引用可点击定位原文 |
| 异常流 | 3a. 检索无结果 → 返回兜底话术 + 建议检索词，`answer_type=refused`<br>5a. LLM 超时（> 20s）→ 返回已检索证据摘要 + 错误提示，可重试<br>5b. LLM 渠道失败 → 自动降级到备用模型，再失败则返回证据列表 |

### UC-02 制度文档入库

1. editor 在前端选择知识库 → 上传 PDF → 填写文号、发布机构、生效日期；
2. 后端返回 `document_id` 与 `task_id`；
3. 后台任务：类型识别 → 文本抽取/OCR → 清洗 → 条文切分 → 切片落 MySQL → 批量向量化 → 写 Milvus；
4. 前端每 1.5s 轮询任务进度；
5. 完成后文档状态置 `ready`，知识库统计刷新；
6. 失败则记录 `error_message`，支持重试。

### UC-03 知识点人工校验（支撑 85% 准确率）

1. editor 打开「知识点管理」，按分类/时效筛选待校验知识点；
2. 系统并排展示：知识点正文 ↔ 来源文档原文（定位到条号/页码）；
3. editor 判定通过 / 存疑 / 驳回，填写意见；
4. 落 `knowledge_point.verify_status` 与 `qa_review`；
5. `GET /kb/{id}/stats` 实时显示「已校验数 / 校验通过率」。

### UC-04 条文关联查询

1. 用户在答案引用卡片点击「查看关联条文」；
2. 前端 `GET /knowledge-points/{id}/related`；
3. 后端按规则返回三类关联：**同文档上下文条**、**同主题跨文档条**（向量相似度 ≥ 0.75）、**替代/被替代关系**（时效标注）；
4. 前端以分组列表展示，点击跳转原文。

## 8. 假设、约束与风险

**假设**
1. 开发期可访问一个 OpenAI 兼容的大模型 API（或校内可用的本地推理服务）；
2. 部署机器内存 ≥ 8GB（Milvus + MySQL + 后端峰值约 5GB），磁盘 ≥ 20GB；
3. 制度文档可由项目组从公开渠道自行收集，无需企业方提供内部资料。

**约束**
1. 一期单机部署，不引入 K8s、不引入消息队列；
2. 不使用 GPU 也可以运行（Embedding 用 CPU 推理，单条 500 字切片约 30~80ms，批量入库需容忍）；
3. 项目周期按 `docs/10` 的 9 周计划执行。

**风险与应对**

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| LLM API 不稳定 / 欠费 | 问答不可用 | 配置双渠道降级；提供「仅检索」演示模式 |
| CPU 向量化过慢 | 入库时间长 | 批量编码 + 模型量化；入库限流后台队列 |
| 扫描件 OCR 质量差 | 召回下降 | 预处理（二值化、去噪、倾斜校正）；人工校对知识点 |
| 知识点凑不够 1000 条 | 验收不达标 | 提前启动知识抽取脚本 + 批量导入模板并行推进 |
| 2 秒时延不达标 | 核心指标失败 | 流式输出 + 缓存高频问题 + 限制上下文长度 |
