# 成员2数据管线修复对接说明

本分支基于成员1后端提交 `9b55852`，修复本地真实数据验证发现的解析、入库和检索问题。

## 主要改动

- 保留法律条号与 OCR 换行，避免清洗阶段丢失制度正文。
- 修复 Milvus search 参数和返回字段读取兼容性。
- 修复关键词查询 SQL 格式化及条号列表参数。
- 导入知识点时校验分类、文件内重复编号、来源唯一匹配和页码；禁止跨知识库覆盖编号。
- 保留审核状态、备注和来源网址；默认草稿；已发布数据必须审核通过。
- 兼容 Excel 原生日期单元格；校验日期、时效状态和难度（1～3，与接口一致）。
- 增加 SQL/Milvus 一致性审计，区分切片与知识点向量，防止误删。

## 接入步骤

1. 审核本分支相对 `member1-backend` 的差异后合并。
2. 来源表需要新增 `source_url VARCHAR(2000) NULL`，模型改动不会自动修改现有数据库。从 backend 目录执行 `python -m scripts.migrate_source_url`；此本地迁移仅允许 finrag，其他环境应由后端成员纳入正式迁移。
3. 重启后端，使新代码生效。本地缓存模型可使用 HF_HUB_OFFLINE=1；团队环境按实际配置决定。
4. 执行单元测试和 `python scripts/audit_data_consistency.py`。试导入脚本依赖成员2本地 runtime 数据，不属于干净环境自动测试。
